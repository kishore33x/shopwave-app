--------------------------------------------------
[Calm pace]

The real problem is lack of clarity and speed.

--------------------------------------------------
Shopwave solves this by providing one clean dashboard for analytics and prediction.

- Real-time style visual summaries
- Category and product-level insights
- AI-style insight statements
- Sales forecasting for upcoming days

[Pause]
This allows business teams to move from guessing to data-driven planning.

8) Machine Learning (Simple Explanation)
--------------------------------------------------
Now let us explain the ML part in simple terms.

We use a Random Forest model for sales prediction.
A Random Forest is a collection of decision trees.
Each tree gives a prediction, and the model combines them.
This usually gives stable and reliable results.

Our ML flow is:
1. Clean data using Python scripts
2. Train the model using historical sales data
3. Generate predicted revenue values
4. Serve predictions to the frontend through API routes

[Pause]
So the ML model learns patterns from past sales and estimates future sales.

10) Code Walkthrough (Simple and Clear)
--------------------------------------------------
Now let us quickly walk through the code flow.

Frontend structure:
- The app pages are in frontend/app.
- Each page has its own file: dashboard, categories, products, predictions.
- Reusable UI parts are in frontend/components.
- Reusable charts are in frontend/charts.

[Pause]
How data moves in the app:
1. A page loads in the browser.
2. The page calls an API route from frontend/app/api.
3. The API route reads processed analytics data.
4. The response comes back as JSON.
5. React components render KPI cards, charts, and tables.

Dashboard code flow:
- The dashboard page fetches summary, trend, category, and product data.
- It passes this data to StatCard, ChartCard, and chart components.
- AI insights are computed from this same data on the frontend.

Categories code flow:
- It fetches category performance once.
- The same dataset powers both the bar chart and pie chart.
- The table uses that same data for percentage and order count view.

Products code flow:
- It fetches top products.
- Search, sorting, and pagination are handled in frontend state.
- This keeps interaction fast and simple.

Predictions code flow:
- It uses the predictions API route.
- The chart and summary cards use the same prediction array.
- If data is missing, fallback values keep the page usable.

Backend and analytics flow:
- Shared analytics logic is in frontend/lib/analytics.ts.
- It reads dataset files and computes summary metrics.
- API routes call these utility functions and return clean JSON.

ML code flow:
- Python scripts in ml/ handle cleaning, training, and prediction.
- train_model.py trains the Random Forest model.
- predict_sales.py generates future revenue values.
- Output is saved as processed files and consumed by the frontend APIs.

[Pause]
So the architecture is modular:
UI components, API routes, analytics utilities, and ML scripts all work together.
